# Private source snapshots

`scripts/snapshot_sources.py` preserves complete source responses privately and proposes public retrieval timestamps and SHA-256 hashes. It uses the same cached responses and content checks as the excerpt verifier. PDFs are preserved as PDF bytes, including scanned PDFs without extractable text that pass the same trailing-end-marker check. Recognised XLSX workbooks and explicitly declared, bounded, CRC-validated ZIP data archives retain their original bytes. ZIP members are never written to disk or executed. HTML, DOCX and explicitly cited content-matching copies retain their original response bytes. Rendered text is a fallback when direct content is unavailable; its manifest identifies the rendering URL and method. A usable HTML response with meaningful recorded quotations but none present in either original extraction view is compared with one rendered copy. Rendered text replaces it only when a quotation matches there; any original quotation match retains the original. This does not claim complete quotation coverage.

For quotation checks, the verifier reads literal string cells from visible XLSX worksheets and UTF-8 `readme.md` or `readme.txt` members of ZIP data archives. It excludes unused shared strings, phonetic annotations, hidden worksheets, formula results and numeric cells. It does not format workbook numbers or evaluate formulas; quotations relying on those values need a separately reviewed source view. Workbooks containing visible chart or dialog sheets are unsupported and need visual verification. These extraction limits do not alter preserved source bytes.

Complete original PDF bytes can be preserved when the primary PDF parser fails, provided an independent verifier PDF view yields nonempty text that passes the shared content checks. The original raw checksum, byte count and trailing PDF end marker are checked first. The end marker rejects truncated prefixes; it does not prove that every page or factual claim is correct. The cached primary extraction_error remains recorded; recovery does not rewrite it as a successful primary extraction. If independent views fail or contain only a rejected response, the original is not accepted through this exception. Parser-failed HTML and ZIP files are not covered. Archive identity needs a substantive match in a usable independent view or an exact hash match against a validated original document.

Run from the repository root after quote verification has populated the cache:

```sh
uv run --locked scripts/snapshot_sources.py --offline --lookup-archives --report work/reports/source-snapshots.json
```

Without `--offline`, uncached original URLs and selected fallbacks may be retrieved. `--lookup-archives` checks an existing archive.ph capture with GET when a declared archive does not validate. The tool never submits a page for capture. For `snapshot_sources.py`, `--apply` explicitly applies the proposed snapshot metadata and validated archive changes to the selected `--data` file; otherwise the dataset is unchanged. Review failed sources and archive-removal proposals in the report before applying them.

Set `AISI_SNAPSHOTS` to a private source directory outside the repository. `snapshot_sources.py --directory` and `check.py --snapshots` override that environment variable. An unset or empty variable leaves the store unconfigured: the snapshot tool exits with a configuration error, and the check command records copies as NOT RUN. NOT RUN blocks completion unless `--allow-skip` is used locally; CI refuses that option. Every copy whose hash the data records must be there: `check.py`'s copies step fails when a recorded `snapshot.sha256` has no checksum-verified file in it. A configured directory that does not exist is also NOT RUN. `check.py` (`--snapshots`) and `verify_excerpts.py --seed-snapshots` read the same directory: a URL missing from the source cache is seeded into the cache from the copy whose hash the data records for that source (`snapshot.sha256`), otherwise from its most recent retrieval in the manifests (for `check.py`, a scratch cache outside the checkout; otherwise the ignored `work/source-cache`), so a fresh clone can verify quotations offline. The bytes are re-extracted and checked against the manifest hash; nothing from the directory is written to tracked files or the build. A write-permission failure uses the ignored `work/snapshots` fallback and is reported. Each copy's private manifest records the requested and final URL, retrieval method and timestamp, MIME type, complete-response hash and relative file path. Source IDs and hashes determine safe filenames. The manifest method identifies the saved copy type; if the cache was first populated under a different role, that value is retained separately as cache_method. Metadata corrections append a row for the unchanged bytes and timestamp; the latest matching row is current. Existing valid copies are retained; a repeated response hash reuses its recorded snapshot timestamp. Failed later requests do not erase an earlier valid snapshot. A rendered fallback does not replace an existing valid original; a positively matching render may replace an original HTML shell without matching body quotations. Retrieval timestamps preserve their recorded RFC3339 precision and offset.

Login, browser-challenge, cookie-settings-only, empty application roots and document-viewer-only responses are not evidence, nor are site error pages served with HTTP 200 (a bare error label after the site name in the title), web application firewall rejection pages and rendered copies (r.jina.ai) that end at the application's loading indicator. Gzip responses are decoded within the same size limit for inspection; saved checksums still identify the original bytes. The recognised English WAM cookie-policy banner is rejected when it is the only rendered content, even when publication metadata surrounds it. A Wayback viewer is followed through its observed same-target, same-timestamp document URL, or one raw replay URL, before judging the capture. An unavailable or unverified raw replay leaves the declared viewer link retained and explicitly unchecked. A demonstrated login, error, cookie-only, empty-render, empty-application, document-viewer-only or missing-capture raw response propagates its rejection and proposes removing the viewer link. Manual content review can also reject a captured shell that generic checks cannot classify. New or replaced archive links must bind to the original URL or a recorded redirect and match a substantive quotation, an informative body title, or validated original document bytes. A www host variant is accepted without a recorded redirect only when the validated document bytes exactly match those of the original; a title or quotation alone cannot waive the URL check. Head titles and navigation alone cannot establish identity. Redirected live responses also require substantive identity. Rate-limited archive lookups are unchecked, not evidence that no capture exists. The report records each declared archive outcome separately from snapshot success; a publisher's cited syndication copy is a distinct case and is not labelled an archive. Invalid `archive_url` values are removed only for demonstrated invalid content or non-capture URLs, while transient failures alone do not erase the declaration. A verified alternative found after an uncertain or transient result is reported without replacing the declared link. Correcting an archive label does not remove the cited copy URL from source excerpts.

Public archive links use Wayback, with archive.today (archive.ph) as a fallback where a usable capture is found. Private evidence copies support verification and are not distributed with the dataset. Access notes identify retained renderings, archive captures and separately cited publisher copies; review these notes when applying replacement snapshots.

## Quotation verification

`scripts/verify_excerpts.py` checks literal quotations against cached source text. Online retrieval is opt-in and the build never runs the tool; `check.py` runs it offline, only for new or edited quotations. Reports and the cache stay in ignored `work/`.

```sh
uv run --locked scripts/verify_excerpts.py --all-excerpts --offline   # audit the existing cache
uv run --locked scripts/verify_excerpts.py --all-excerpts             # also retrieve uncached copies
```

The default checks decisive excerpts; `--all-excerpts` checks every quotation and `--all-sources` also retrieves sources without quotations. Retrieval tries each declared live and archive copy and one rendered fallback, reuses cached attempts (including failures: use a fresh `--cache` for a new attempt), and by default runs four workers with one second between request starts to the same host and a 25-second timeout. It rejects the same non-evidence responses as the snapshot tool (above). Exit status 1 means at least one quotation needs review.

Matching normalises Unicode composition, whitespace and quotation marks only. It ignores spaces between Japanese or Chinese characters, and PDF line breaks with Japanese or Chinese text or CJK or full-width punctuation on one side and one of those or a digit on the other; it rejects a match that cuts through a number (adjacent digits or number separators); ambiguous adjacent numbers need review. A quotation must match within one view: for HTML, the full text or a view without hidden accessibility text (both keep noscript text, which does not show that it is visible with JavaScript on); for PDFs, independent default, layout and, when `pdftotext` is installed, Poppler views, tried even when the primary parser fails. The evidence group includes `fonttools` because pypdf needs it for embedded CFF fonts. A match shows the words occur, not that they support the claim.

Reports separate mismatches, transport failures, uncached sources, rejected responses, unextractable documents, extraction failures and storage failures, and record the extraction version and whether Poppler was available. Flagged for review: a quotation found only outside its declared URL (`matched_other_copy`), matches only in hidden HTML text or in an undeclared rendered copy, and rendered Jina text, which can contain spoken accessibility expansions. Non-matches need editorial review: readable PDF glyphs, especially Arabic and image-based text, can stay visual evidence with the page recorded in `access_note`; a rendered publication timestamp is labelled as metadata, not body text. Corrupt cache metadata or checksums stop the audit. Some sources reject the Python trust store but pass platform TLS verification; an imported response of that kind keeps its real retrieval method, timestamp and complete-response hash.

## Legacy archive candidates

`data/reference/archive_urls.json` holds earlier Wayback lookups, not verified evidence. `uv run --locked scripts/archive_sources.py --apply` retrieves each candidate capture into `work/source-cache` (`--offline`: cached captures only) and writes its URL only if it passes the archive, content and document-identity checks; existing canonical archive URLs stay unchanged. Without `--apply` the tool does its original lookup and Save Page Now requests. The snapshot workflow never calls it.

## File hash and text hash

`sha256` proves which file is held. `text_sha256` hashes the copy's normalised main text under the versioned rule `text_scheme`, whose definition is the schema description of `sources[].snapshot.text_sha256`; it is how the tool tells a real content change from rotating tokens, counters and page furniture. When a rerun replaces the cited copy is an editorial rule in `dataset.method` (source copies). In the tool: a quotation is bound to the source when its excerpt names no URL, the source URL or its `archive_url`. A text-hash difference (`text_changed`, another scheme or none, or no text in the new copy) is then checked against the bound quotations, reading both copies through the same verifier views (primary text, visible HTML, PDF views): the new copy is proposed only as `bound_quote_missing` (a quotation the cited copy carries is missing from it) or `cited_copy_lacks_bound_quote` (it carries one the cited copy lacks); a quotation found in neither copy decides nothing. Otherwise the report records the change and its `bound_quotes` counts, and the cited copy is retained. Without bound quotations the text-hash difference alone proposes the new copy. A copy whose text is unchanged is retained; a cited copy no longer held privately is replaced (`previous_copy_missing`). Retained copies keep their timestamp and the new bytes are not saved. Any change to the rule, or to the extraction it reuses (including a parser upgrade that changes extracted text), is a new scheme: bump `TEXT_SCHEME` and re-hash every stored copy once, from the copies the published hashes name, never from new downloads:

```sh
uv run --locked scripts/snapshot_sources.py --rehash --apply --report work/reports/source-rehash.json
```

`--rehash` never fetches; a source whose cited copy is missing is reported as `previous_copy_missing` and left unchanged.

Public sources may contain `snapshot.retrieved`, `snapshot.sha256`, `snapshot.text_sha256` and `snapshot.text_scheme`. CSV exports flatten these as `snapshot_retrieved`, `snapshot_sha256`, `snapshot_text_sha256` and `snapshot_text_scheme`; no private paths or raw source bytes are exported. Snapshot success verifies preservation and content identity where required, not the truth of every factual claim. The current downloader has a finite 128 MiB response limit. Larger files remain explicit failures requiring a reviewed change or separate retrieval.

## Change monitor

`scripts/monitor_sources.py` checks every source once and compares what it gets with the copy the source's snapshot hash names. It never changes the dataset, a manifest or a cited copy. Routes, in order, the first clear answer deciding:

1. A source without a snapshot hash is not fetched: `skipped`.
2. The plain request (honest User-Agent, per-host pacing). Classes: unchanged (same file or text hash), trivial, substantive (a bound quotation the cited copy carries is missing, or, for a like-for-like copy without such quotations, no long run of the cited text survives), gone (404, 410, host no longer resolves), blocked (refuses automated readers) and failed (transient or tool failure).
3. For blocked and failed sources, headless Chromium (`scripts/monitor_browser.py`, one browser, one page at a time), then r.jina.ai with its cache bypassed. Both are live checks, labelled with their route. A fallback copy is never like for like: it is trivial only when every quotation the cited copy carries is present (or, without quotations, a long run of the cited text survives), substantive only when both fallbacks reached a comparable copy and miss the same quotation, and otherwise `failed` (`not_comparable`, `fallback_quote_unconfirmed`), moving on. A comparable copy carries at least one of the cited copy's quotations, or, without quotations, a long run of its text.
4. When no live route answered, the newest Wayback capture: `archived`, with the capture date. A live copy missing a quotation still outranks a capture that has it. It is an archive observation, never a live check. A check whose URL or final URL is an archive capture is an archive observation on any route.

Each run appends one line per source to `checks/checks.jsonl` beside the snapshot directory (run, dataset revision, route, every route tried, hashes, each quotation's presence by text hash, class and reason, verifier versions), records its start and finishing steps in `checks/runs.jsonl`, and keeps checked copies that differ from the cited copy in `checks/responses/` under their hash. Nothing there is pruned yet. A fallback copy is evidence in the log, never a new snapshot. `--resume RUN_ID` finishes an interrupted run (Ctrl-C, a stop, the four-hour `--deadline-hours`) without fetching the sources it already has, and refuses a changed dataset. `--digest` sends the run's summary with the notification command the host sets in `AISI_DIGEST_COMMAND` (title and body as its last two arguments); an undelivered digest fails the run.

Headless Chromium runs only inside the shared browser lock (`scripts/browser_lock.py`, `$AISI_BROWSER_LOCK`, by default `$XDG_RUNTIME_DIR/aisi-browser.lock`), which the browser gate and the build's pre-render also take, so the monitor waits while a gate run uses the browser, for at most `--browser-wait` seconds per run, and skips the headless route when that runs out. The report (`monitor.md`, `monitor.json`) also lists the unreached sources with what was tried, due `next_check` dates and a discovery queue of recorded searches:

```sh
uv run --locked scripts/monitor_sources.py --report work/monitor
```

The weekly run is a scheduled job on the maintainers' host, configured outside this repository, and off until the owner switches it on.

`--rereads` fetches nothing: it replays the whole check log into the tracked `data/rereads.json`, each bound quotation's re-read state and dates (keyed by source ID, then quotation hash), and is that file's only writer (`scripts/rereads.py`; states, expiry and alerts in [claims design section 4](design/claims-1.1.md#4-freshness-and-expiry)). The file carries states and dates only, never the log's paths, responses or texts; regenerate it after each run and commit it as data, so the build and CI need no private store.

```sh
uv run --locked scripts/monitor_sources.py --rereads
```

`--lead URL` checks a page that discovery read but did not cite against a private seen-leads ledger (`discovery-leads.jsonl` beside the snapshot directory): new, changed or skip (text hash unchanged). Add `--verdict irrelevant|not_primary|duplicate|candidate --reason "..."` (and `--duplicate-of SOURCE_ID`) to record a reading.

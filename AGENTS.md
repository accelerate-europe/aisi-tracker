# Agent guide

The map for agents and editors working in this repository. It routes; it does not restate rules. `CLAUDE.md` points here.

The staged `check.py` command and shared pre-commit/CI steps run the automated checks. Every commit also gets an independent review of exactly what is staged, named in a `Reviewed-by:` trailer.

## Repositories and branches

- The public repository `accelerate-europe/aisi-tracker` holds the code, page, data, schema, docs, tests and CI, and all development happens there. `main` is the live site: every push to it deploys, so it moves only with the owner's Go, as a fast-forward to a reviewed `next` commit ([release runbook](docs/release.md#4-move-main-and-deploy)). `next` is where work lands: branch from `next`, and merge reviewed branches into it. Reviewed branches and `next` may be pushed freely; moving `main`, a release, a Zenodo action, deleting a branch and rewriting public history need the owner's Go.
- Branches, commit messages and data on `next` are public the moment they are pushed, before any release. Before every push the pre-push hook runs gitleaks and the internal-names scan on the commits being pushed, files and messages, and refuses the push without the private terms file; CI runs both again. Never bypass it with `--no-verify`. Only a remote listed in the clone's `aisi.leakScanSkipUrl` git setting is left unchecked: set it, with the address, only in a checkout of the private repository.
- Commit messages are public: keep the `Co-Authored-By:` trailer but leave out any `Claude-Session:` trailer, and quote no local or scratch paths.
- The maintainers' private repository holds what stays private: the owner docs (`docs/history/`, `docs/review.md`, `docs/decisions.md`, `docs/claims.csv`) and `data/internal/`. Read them from its checkout; `scripts/state_languages.py` and `scripts/protocol_checks.py` find `data/internal/` through `AISI_INTERNAL`. Source copies, research passes and the private terms file live in the private store (`AISI_SNAPSHOTS`).

## Where things live

- `data/aisi.json`: the authored dataset, the single source of truth. Editorial rules are in its `dataset.method`; status definitions in `dataset.status_definitions`.
- `schema/aisi.schema.json`: the published download contract. `references.authored_schema` derives the authored-input contract from it; generated fields are forbidden there.
- `scripts/published.py`: the shared primary-facts, stable-reference and field-citation pipeline, used by every consumer. `scripts/build.py` with `method_checks.py`, `shared_claims.py`, `release_checks.py` and `reader_text.py`: the invariants, enforced at validation. `tests/`: their regression tests.
- `scripts/row_checks.py`: the Head, Reports to and Partners rows: cross-field checks, required evidence pointers and the generated card selection ([design](docs/design/schema-1.0.md#head-reporting-line-and-national-partners)). Relation words and the cyber tail come only from `dataset.vocabularies`.
- `scripts/flag_checks.py`: testing capacity and model access (downloads, API and the page's Testing and access groups) and staffing model (downloads and API only): checks beyond the schema, required evidence pointers, the attribution guard and the derived model access value ([design](docs/design/schema-1.0.md#testing-capacity-and-model-access), [staffing model](docs/design/schema-1.0.md#staffing-model)).
- `scripts/agent_files.py`: files for agents and scripts that `build.py` generates from the published data: the static per-record API under `api/v<major>/`, the orientation text (the API index and `llms.txt`, linked from the page's "Using the data"), the page-head JSON-LD, `sitemap.xml`, `robots.txt`, the Atom feed of releases `feed.xml` (from `changelog`), the tracked `CITATION.cff` and `.zenodo.json`, the Zenodo record metadata that `scripts/zenodo_metadata.py` sets after each release, and the `PUBLIC_URL` site address. `tests/test_api.py` checks the API against `aisi.json`.
- `site/index.html`: the page. The build saves it pre-rendered (`scripts/prerender.py`); the comment at the top of its script says how the script takes over. Its design principles are the comment at the top of its `<style>`.
- `scripts/check.py`: the one check command. `scripts/check_page.py`: the browser gate it runs. `scripts/contact_sheet.py`: the screenshot sheet. `scripts/sweep_page.py`: the release's full page sweep, run on CI by `.github/workflows/sweep.yml` ([release runbook](docs/release.md#3-release-check)). `scripts/export_scan.py`: the scan of the public export, and of the commits being pushed, for internal names, run by the `export` step (with gitleaks) and the pre-push hook `.githooks/pre-push`; its private terms file lives outside the repository, beside the private store.
- `docs/dependencies.md`: how scripts run from locks, how locks change and which browser the scripts use. `scripts/dependency_checks.py` checks it in the lint step.
- `.github/workflows/pages.yml`: CI on every branch (fast checks, build, browser gate in four shards; the `build` job is the required check) and, on public `main`, the release checks and the Pages deploy; the slide map is built too, but a map failure does not block publishing. `scripts/release_tag.py` and `scripts/zenodo_metadata.py`: the GitHub release tag and the Zenodo metadata ([release runbook](docs/release.md)).
- `scripts/ci_run.py`: waits for CI on a commit and names the failed jobs (`wait`), or downloads and safely extracts the site CI built for it (`site`), for an audit or a sweep of CI's exact build.
- `scripts/monitor_sources.py`: the source change monitor, its fallback routes, the private check log and the weekly digest (`scripts/monitor_browser.py`, `scripts/monitor_digest.py`; [change monitor](docs/source-snapshots.md#change-monitor)).
- Other tools: `scripts/slide_map.py` (static Europe map for slides; `AISI_MAP_FONTS` sets its fonts), `scripts/make_roster.py` (the coverage roster `data/reference/roster.csv`), `scripts/social_preview.py` (regenerates the social image: `uv run --locked scripts/social_preview.py`), `scripts/rule_tables.py` ([rule tables](docs/consistency.md#rule-tables)) and the legacy `scripts/archive_sources.py` ([archive candidates](docs/source-snapshots.md#legacy-archive-candidates)).
- `docs/design/schema-1.0.md`: the download contract and how rules are represented. `docs/release.md`: the release runbook; `docs/launch.md`: one-time launch setup. `docs/consistency.md`: what the consistency checks cover, and the rule tables. `docs/source-snapshots.md`: private source copies and quotation verification. `docs/research-passes.md`: research passes, their private folders and `scripts/research_pass.py`.
- `docs/history/`, `docs/review.md`, `docs/decisions.md` and `docs/claims.csv`, in the private repository checkout: superseded notes, not current rules (do not act on them), the maintainers' review protocol, the owner's binding decisions, one line each, and the public claims re-checked at each minor or major release. `.gitattributes` marks them and `data/internal/` `export-ignore`, and the pre-push scan refuses them in a pushed commit.
- `work/` (gitignored): reports, caches, screenshots and scratch files. Never commit them.

## Change type, files, done

| Change | Edit | Also |
| --- | --- | --- |
| A fact | the record in `data/aisi.json`, its `sources` entry and an excerpt whose `supports` points at the claim | name the research pass in a `Research-pass:` trailer ([research passes](docs/research-passes.md)); when you open a source, record every fact it carries for the record before filling a field, and list leftovers in the handback; advance `check.last_checked` only after a full re-check; version, `as_of` and changelog per the [release runbook](docs/release.md#2-the-release-commit) |
| A status | the jurisdiction `timeline` event; the build derives status and dates ([timeline rules](docs/design/schema-1.0.md#timeline-and-status)) | excerpt on the event |
| Funding amount or exchange rates | primary amounts or ECB rate inputs in `data/aisi.json`; EUR results are generated | |
| A field | schema, `build.py` export and tables, tests | from public 1.0.0: minor for additive fields, major for breaking changes |
| An editorial rule | `dataset.method` first | `uv run --locked scripts/rule_tables.py` and its impact table before editing records; reread affected reader summaries, then `uv run --locked scripts/method_copy.py refresh <summary-id>` |
| Page copy | `site/index.html` | visual pass; the gate checks generated counts and facts in copy, that accessible names and headings exist, and that a qualifier sits in the same element as its value; checks that still compare fixed wording word for word are being removed (test strategy D1), so a rewording may still need one of them updated |
| Page layout or style | `site/index.html`, its principles comment if a rule changes, and a gate check for a new rule | visual pass |
| A release, or a deploy without a version | the [release runbook](docs/release.md) | `check.py --release` |

Done means: the change is staged, `uv run --locked scripts/check.py --skip-browser --base origin/next` passes (it starts no Chromium: build, browser gate and sheet are left to CI and to visual passes; use the remote branch or tag the work is based on instead of `origin/next` where it differs; a local branch that differs from its upstream is refused), the branch is pushed (the pre-push hook passed) and the build and browser gate have passed on CI for that commit (merges are not blocked on CI, so check its result yourself: `uv run --locked scripts/ci_run.py wait <sha>`), you have read the report, and the commit has had an independent review of the staged diff. Run the full `check.py` locally, which starts Chromium, only when a change needs it (a visual pass needs its sheet and served build), one browser at a time on a shared host. A visual pass means opening each Where to look link in the report on the served staged build at 1440, 1000 and 390 px, light and dark, and judging it against the design principles at the top of `site/index.html`.

## Commands

- `uv run --locked scripts/check.py`: checks exactly the staged snapshot and writes nothing into the checkout. It prints the report path.
- `uv run --locked scripts/check.py --only fast`: validation, lint, the export scan and tests (about 1.5 min; tests run in four pytest-xdist workers). The export scan needs `AISI_SNAPSHOTS` or `AISI_EXPORT_TERMS` in the committing shell; without it the scan reports NOT RUN.
- `uv run --locked scripts/check.py --changed --fail-fast --base origin/next`: only the steps the changed files need, stopping at the first blocking result; a data or page change still runs the build and the whole browser gate. This is also the pre-commit hook; install it once per clone with `git config core.hooksPath .githooks`.
- The browser gate (`scripts/check_page.py`, about 1.5 min) runs its checks as independent jobs in parallel processes: `--jobs N`, by default `AISI_GATE_JOBS` where the host sets it, else the CPUs up to 8 and up to what the memory holds at 4 GiB a job (on a 7.5 GB machine, two jobs timed out under memory pressure). A job count the memory does not hold is NOT RUN with the fix, in `--preflight` and when the gate starts. Errors are reported in the sequential order, so the report does not depend on N; `--jobs 1` runs the jobs one after another, which helps when debugging one check. CI builds the site once, splits the browser jobs over four machines (`check.py --gate-shard K/4`) and reports them from the shard results in the `build` job (`--gate-merge`), which is the required check.
- Chromium on a shared host goes through one lock, `scripts/browser_lock.py`, which the gate, the build's pre-render and the source monitor take ([change monitor](docs/source-snapshots.md#change-monitor)).
- `uv run --locked scripts/flake_detector.py --dist DIR --job ID[,ID] --runs N` (test strategy D5): runs browser jobs again and again on one build, each in a fresh process, interleaved, within a 10-minute budget by default, and keeps every attempt; `--list-risky` names the default set. Its attempts run with `--skip-static` (the job alone, no render or static checks). No check is ever retried to turn red into green; re-running a CI run whose jobs never started (a lost runner, or Actions refusing to start jobs) is not a retry, as there is no result to retry. A demonstrated harness flake may go into `scripts/quarantine.json` with its owner, issue and an expiry at most 30 days ahead: its findings are then report lines until the expiry, after which it blocks again. Browser runs on a shared host go one at a time.
- `uv run --locked scripts/check.py --preflight`: can this agent run every step (Chrome, Node, the private store)? If a step would be NOT RUN, say so in the handback and name who must run it; never report it as passed.
- `uv run --locked scripts/build.py --out DIR` builds the site. The locked Playwright's Chromium is a build requirement (install it with `uv run --locked scripts/check_page.py --install-chrome`): `scripts/prerender.py` saves the page as rendered in headless Chromium, and the build fails without it (there is no NOT RUN path for the build); `uv run --locked scripts/build.py --update-readme` regenerates the README citation, current counts and definition blocks, `CITATION.cff` and `.zenodo.json`, the only build or check command that writes a tracked file.
- New earliest credited work needs a hand-worked entry in `tests/fixtures/earliest_credit.json` (institute, lineage and the sources whose excerpts credit it, read from the sources, never from the export); an unknown institute/lineage pair fails the gate with its key. The entry travels with the DATA commit, and its reviewer checks it against the source.
- Regenerated README citation/count/definition blocks, `CITATION.cff` and `.zenodo.json` travel with the DATA change that changes their inputs; prose or generator changes remain CODE.
- Stable selectors use permanent record IDs, or the documented natural keys for output lineage, currency and membership body. Correcting a natural key requires updating its bindings; see the [download contract](docs/design/schema-1.0.md#source-excerpts).
- The dataset is several MB: inspect single records with `jq` or a short Python snippet rather than reading the file.

## Standing rules

- Never invent or guess URLs, dates, names or figures. Every new fact needs a source you retrieved, chosen as `dataset.method` (Source preference) sets out. For a JavaScript-only page try `https://r.jina.ai/<URL>` once, then record an `access_note`.
- Configure the private store with `AISI_SNAPSHOTS` ([source snapshots](docs/source-snapshots.md)). Source copies go there through `scripts/snapshot_sources.py`, never only into a clone's `work/`; `check.py`'s copies step fails when a recorded snapshot hash has no file there.
- Before editing a quotation whose source is not cached, fetch it or save a snapshot first; otherwise the compare step reports NOT RUN.
- British spelling, no em-dashes, plain words, in data text and docs (`reader_text.py` enforces part of this).
- One home per kind of rule: editorial rules in `dataset.method`, field meaning in schema descriptions, invariants in code and tests, design rules in the page's principles comment. Link to the home; do not restate it.
- Select data by key or by an explicit, documented order with a tie-break; `[0]`/`slice(0, n)` on data is allowed only where a check enforces the order or uniqueness.
- Fix the class, not the instance: when you fix a defect, look for the same defect elsewhere.
- Questions: one question per decision, recommended option first.
- Agents follow the full rules in `dataset.method` (rendered at `method.html#<rule-id>`), never the reader summaries, which are owner copy.
